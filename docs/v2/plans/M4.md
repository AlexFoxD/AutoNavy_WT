# M4 — Owned telemetry and offline consumers

Approved scope: TEL-01 / A15–A17, lifecycle integration A18–A19, offline A32.

1. Add fake-Session tests first for immutable parsed snapshots; status/JSON/schema/nonfinite/size failures; missing or duplicate Player; conservative exact Ship/red classification; empty zones; receive-time preservation, consumption TTL, recovery and map changes. Observe RED before implementation.
2. Implement `TelemetryService(settings, *, session_factory=None, clock_ns=..., join_timeout_s=...)`. Only its serial worker constructs/uses/closes one Session. `start`, signal-only `request_stop`, bounded `close`, `snapshot`, and `map_image` form the lifecycle/read API. Objects target 10 Hz without backlog, default tuple timeout (0.5, 0.5), stop-aware exponential backoff.
3. Cache one metadata record and one verified encoded map image in memory, each with its own receive time and identity. Stream with byte limits, verify bounded image dimensions, never write assets or routes. Metadata refresh uses 30-second TTL and immediate recovery refresh; image refresh is independently due. Map/error/stale recovery changes local generation, with no invented server identity.
4. Replace `info.py` and `toolkit/map.py` network paths with explicit snapshot/source facades. Missing/stale Player yields unavailable values. Compatibility callers must pass a service/snapshot; no global lazy network fallback.
5. Wire the real Application after template/capture startup; replay uses inert telemetry and supports explicit offline injection. Store consumption-checked `last_snapshot`; close all resources despite individual failures while preserving M2 shared cleanup completion/error semantics. Extend existing fake-capture tests with inert injection so every automated transport remains fake.
6. Focused tests while iterating, then once run `.venv/Scripts/python.exe -m pytest tests -q -k 'not test_batch_launcher_does_not_permanently_change_execution_policy' --tb=short`, compile owned code, scoped diff check, self-review and scoped local commit. Coordinator independently reviews.

Requests connect/read timeouts are inactivity/connect budgets, not a total wall deadline. Event cancellation cannot interrupt arbitrary socket/native calls; close reports a worker still alive after its join allowance and the daemon owns eventual Session cleanup. Other resource cleanup must proceed independently. No localhost/device/input checks are permitted.

## Implementation verification

Implemented all six steps above. Focused telemetry/application/capture/vision check: 71 passed in 27.58s. Full permitted regression: 241 passed, 1 deselected in 70.86s; the known launcher side-effect test remains excluded until M8. Compileall and scoped diff check passed. Independent coordinator review is the next gate.

Public consumption API: `TelemetryService.snapshot()` and retained `TelemetrySnapshot.at(now_ns)` enforce object/metadata TTL independently. `Application.last_snapshot` rechecks its retained snapshot at access. Generation is locally inferred from observed map metadata key changes, availability recovery and object TTL gaps, including gaps crossed inside a request; it is not a server session ID. Identical-map sessions with no observed interruption cannot be distinguished. Hostiles require literal Ship plus one of the two documented red RGB values; missing/duplicate Player, malformed known data and zero heading are unavailable.

One bounded encoded MapImage is cached in memory, with its own key/generation/receive time and TTL. Consumers receive PNG/JPEG bytes and decode using actual dimensions; source maps and route assets are never written. Legacy info/map helpers now require an explicit source; old no-argument navigation entrypoints are outside the supported runtime pending M6 migration.

Application starts telemetry only after template validation/capture startup; replay defaults to OfflineTelemetry. Resource cleanup aggregates capture/telemetry errors and preserves shared completion across callers. Concurrent close allowance accounts for both resource budgets. M5 must neutralize input before those waits and take current telemetry/stop/generation guards at dispatch. A retained value cannot learn of later failures without a fresh service read.
