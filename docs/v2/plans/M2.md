# M2 Capture ownership and geometry implementation plan

> For agentic workers: execute this coordinator-assigned task sequentially with the installed test-driven-development and verification-before-completion skills. No additional subagents.

**Goal:** One explicitly started capture owner, bounded waits and shutdown, stable latest packets, and packet-bound Windows client geometry through the actual application factory.

**Architecture:** Replay remains finite and in-process. Live DXcam alone runs in a spawned process, sharing one fixed pixel allocation and bounded metadata under timeout-based locking. The parent owns immutable FramePackets and a latest-only slot. Immutable geometry snapshots describe client/frame/content coordinate transforms; Windows APIs remain lazy and confined to the live child.

**Tech stack:** Windows x64, CPython 3.11, pinned DXcam 0.0.5, NumPy, standard multiprocessing/threading/ctypes; no dependency changes.

**Spec:** docs/v2/SPEC.md sections 6/8, CAP-01/CAP-02/GEOM-01/LIFE-01/APP-01. M1 contracts: docs/v2/evidence/M1.md.

## Constraints and inspected boundaries

- Preserve English development, legacy 1280x720/100% profile, no live device/input test, no push/merge/system changes. Other workers own shared records.
- DXcam `create(device_idx=0, output_idx=None, region=None, output_color='RGB', max_buffer_len=64)`, `grab(region=None)`, `release()` are present in 0.0.5. Its import enumerates adapters. Import only inside explicit child startup.
- `get_latest_frame()` waits indefinitely; `_on_output_change()` retries COM reconstruction without a stop condition. Use managed `grab` polling at configured target cadence in a reclaimable process. Configured FPS is a target. Repeat off means `None` is not published; repeat on explicitly republishes the last pixels only under identical geometry, with no claim of a new presentation.
- Selected camera `_output.desc.DesktopCoordinates` determines output-relative crop; Win32 monitor enumeration indexes are never substituted. Missing/minimized/outside-output windows fail closed.

## Shutdown contract for later M5

Application.stop signals capture cancellation immediately, without joining. Application.close is the bounded resource-wait boundary. M5 must cancel/release physical input before that boundary, independently of capture errors. M2 does not acquire physical input or register hooks.
