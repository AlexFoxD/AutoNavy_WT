## Actual implementation

- autonavy/capture/obs.py: independent OBSSource, constructor/import inert; lazy OpenCV VideoCapture construction in explicit start, selected through factory inside ProcessCapture child. Exactly `VideoCapture(device_index, API)` with CAP_ANY/CAP_DSHOW/CAP_MSMF. No candidate enumeration, device-index fallback, RGB round trip, private backend or OBS control API.
- Requests CAP_PROP_FRAME_WIDTH, CAP_PROP_FRAME_HEIGHT, CAP_PROP_FPS and CAP_PROP_CONVERT_RGB=1. Reads getBackendName and reported width/height/fps/convert_rgb. Set result is not negotiation proof; uint8 three-channel BGR ndarray and configured canvas dimensions are validated before publication. Invalid layouts are not mislabeled BGR in delivered diagnostics. Nonfinite reported values become null.
- Failure semantics: unopened camera releases its object; consecutive unsuccessful reads yield no-frame or an explicit stale repeat below read_failure_limit, then raise at limit. A valid acquisition resets failures. Exceptions/malformed frames fail immediately with selected-device context. Partial startup preserves original and cleanup failure messages. Release is idempotent at source ownership boundary and may block only in the supervised child.
- New successful identical images get new receive times. Artificial repeats retain an owned copy and original receive age. Changed geometry invalidates repeat cache, including returning to previous bounds. Source render timestamp/clock remain absent, not inferred from pixels or capture position.
- CaptureSample diagnostic payload transported with frame under existing timed lock and 8192-byte metadata limit. ProcessCapture.diagnostic exposes a deep copy of the latest committed publication's diagnostic. No lifecycle/start/cancel/reclaim synchronization changes. App logs capture_source once per source generation and existing capture_geometry for new geometry.
- GeometrySnapshot has content_center and pure profile_to_frame/frame_to_profile scaling transforms. Native reference-size content anywhere within a larger canvas can be recognized only if profile is legacy-1280x720, reference/client/content are exactly 1280x720, UI scale 1, DPI 96. Scaling transforms do not authorize scaled recognition.
- source_geometry applies manual OBS content rectangle and index/API source_id consistently in OBSSource and LiveWindowGuard. Current Windows client bounds/DPI/window handle/profile plus source identity/calibration must match before physical-marked dispatch. No desktop fallback.

## M8 operation/setup handoff and limitations

Use a manual game-only OBS source and start Virtual Camera yourself. Configure capture.backend='obs', explicit device_index, obs_api='dshow' or 'msmf' (auto selects an API for that same configured index), pixel_format='BGR', width/height equal delivered OBS canvas. Set geometry.obs_content_rect to calibrated [left,top,right,bottom] of unscaled game content. Example asymmetric 1600x900 canvas: [100,50,1380,770] contains native 1280x720 content; its frame center is (740,410) and maps to client center independently of desktop origin.

Configured camera index is operator trust. getBackendName identifies an OpenCV API, not a friendly device name or verified OBS camera. Diagnostics deliberately state device_identity_verified=false. The application does not discover cameras; manually verify index/output/calibration before any separately authorized physical-input validation. OBS Program/Preview/Scene/Source changes cannot be detected from these image properties and require rechecking calibration. Source latency/game-render time remains unknown. No FPS/latency benchmark or OBS speed advantage claimed. DXcam stays default.

Runtime capture_source logs requested/reported/delivered separately on the first delivered frame of each source generation. Failed opening/invalid delivery reports context even without a successful frame. Geometry diagnostics report source identity, actual canvas, content/client rectangles, effective scale, profile support and desktop center. Frame shape is authoritative; reported get() size can disagree truthfully. No automatic resize fixes mismatch.
