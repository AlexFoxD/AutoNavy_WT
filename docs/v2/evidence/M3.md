## APIs for subsequent milestones

`FrameContext(packet: FramePacket, *, max_entries=64)` owns one packet and a bounded LRU derivative cache. `.roi(frame_rect)`, `.bgr(frame_rect)`, `.gray(frame_rect)`, `.hsv(frame_rect)`, `.mask(frame_rect, lower, upper, morphology_size=1)`, `.edges(frame_rect, settings, *, mask=None)`, `.profile_roi(profile_rect)`, `.debug_image()`, `.cache_size`. Rectangles are integer exclusive-right/bottom boxes. Derivatives are read-only; `debug_image` is an opt-in full-frame copy. Profile ROI translation requires packet geometry and unscaled content dimensions; it adds content_rect left/top, never desktop left/top. Unsupported scaling raises a descriptive ValueError. Geometry's stricter recognition predicate remains unchanged for M7.

`TemplateRegistry(*, max_entries=64)`, `.register(name, image, *, version=1, black_mask=False)`, `.image(name)`, `.prepared_image(name)`, `.edges(name, *, profile_id='legacy-1280x720', settings=VisionSettings())`, `.from_settings(settings)`, `.names`, `.cache_size`. Registry owns source image copies; replacement invalidates that name's edge versions. Edge key includes name, template version, profile id, preprocessing version, Canny input/thresholds and black-mask mode. Registry is pipeline-owned and not a shared cross-thread mutation service. `prepared_image` preserves the legacy lock HSV black mask; normal hot-path calls reuse cached edges.

`match_template(context, registry, name, frame_roi, threshold, *, settings=VisionSettings(), mask=None) -> MatchObservation`. mask is `(lower_hsv, upper_hsv, morphology_size)`. `match_edges(background_edges, template_edges, threshold)` is the one underlying matcher and rejects oversized/invalid/constant inputs and nonfinite/empty score surfaces. Missing required assets propagate TemplateError. Invalid ROI/oversize/nonfinite result becomes unavailable, with score=None and a reason. A finite negative match remains available with matched=False and finite score.

Frozen `MatchObservation` fields: publication_id, source_generation, geometry_id, available, matched, score, frame_box, desktop_center, reason; `.frame_center` computes integer center only when matched. Desktop coordinates are computed solely through that packet's geometry. Frozen `DegreeObservation` fields: publication_id, source_generation, geometry_id, available, degrees, reason.

`detect_degree(context, *, settings=VisionSettings(), roi=None, debug_image=None) -> DegreeObservation`. Optional roi is frame-relative; default heading profile ROI is translated through packet geometry. Geometry-free pure fixtures may use the configured frame ROI, but the runtime pipeline marks all geometry-free recognition unavailable. `angle_from_mask(mask)` retains the legacy largest-contour triangle/line estimator, no-op 1x1 morphology is skipped, zero direction/no valid polygon/no contours returns unavailable. Values use signed degrees [-180,180), with -180 half-turn tie. `toolkit.deg_cal.get_deg(selected)` accepts only an explicit FramePacket, FrameContext or BGR/BGRA heading ROI; never captures and never defaults a missing estimate to zero.

`VisionPipeline(settings, registry=None)` loads selected assets if none supplied. `.observe(packet) -> VisionObservations` creates one context for this packet and all detectors. `.begin_battle(packet)` initializes an owned ammo baseline. Baseline matching treats current ROI as background and baseline as template, threshold .9, checks generation/geometry and permanently invalidates after any observed change. Call begin_battle again after a new battle or reinitialization.

Frozen `VisionObservations` holds packet, immutable matches mapping, degree, recognition_supported, reason, optional debug_image. Recognition support requires packet geometry's predicate and matching configured profile id/reference dimensions/UI scale. Missing geometry and unsupported profiles produce named unavailable matches and degree; no actuation can be inferred from them.

Match keys are all GAME_ASSETS legacy symbols, plus `aim`, `crash_warning`, `crashed`, `ammo`, `confirm1_queue`, `confirm2_queue`, `start_battle_end`. They preserve start/join/menu/end/research/purchase/lock/fire markers for M5. Defaults: general .8, start .9, join .9, confirmation .95, queue confirmation .6, research .7/follow-up .6, purchase confirmation .6, WT logo queue .6, statistics .7, aim and lock .3, crash warning .2, crashed .3, ammo .9, battle-end start .8. Existing configurable settings override the corresponding defaults. Purchase recognition is only an observation; M5 must pause spending prompts per specification.

`Application.vision` holds the runtime pipeline after startup; `.last_observations` is initially None and then the most recent immutable observation bundle. M5 can call `.vision.begin_battle(selected_packet)` at battle initialization and consume the bundle using packet receive time/source generation/geometry. Vision introduces no input or telemetry calls.

Compatibility: scn.match_img returns `(frame_center, score)` or `(-1, score)`; match_img_ltrb returns `((left_top, right_bottom), score)` or `(-1, score)`. Coordinates are frame-relative; old global RECT desktop offset is removed in favor of packet geometry in actual callers. img_map.load(settings=None) is explicit; legacy symbol attribute access lazily loads the registry. `firesystem.fire_control(settings, packet=None, *, pipeline=None)` exposes `begin_battle(packet)` and `lock_and_fire(packet)` returning observations only.
