## Exact contracts for subsequent tasks

- `create_capture(settings: Settings) -> Capture`: explicit replay/DXcam selection. Factory construction acquires nothing. M7 can select `ProcessCapture(settings, source_factory=OBSSource)` once its real child-local adapter exists.
- `Capture.start() -> None`, `read(timeout: float | None = None) -> FramePacket | None`, `stop() -> None`, `close() -> None`. `None` means finite EOF or cancellation; `CaptureTimeout(CaptureError(RuntimeError))` means the caller's wait budget expired without a new publication. A healthy static/no-new-frame stream remains started. Native startup/read errors are `CaptureError`. Application continues after no-frame timeout and checks stop each time; true errors return exit 3.
- `ProcessCapture(settings, *, source_factory=None)`. Default factory is `DXcamSource`. `read(timeout=0)` polls; omitted timeout uses `capture.frame_timeout_s`. One runtime reader drains transport; all other consumers retain packet objects or read `capture.latest`. M5 should pass the control tick budget rather than the default one-second wait when action deadlines are active.
- `ProcessCapture.request_stop() -> None` signals cancellation, closes/wakes the latest slot and signals the child without joining. `stop()` adds bounded process reclamation and permits restart. `close()` is terminal/idempotent and reports child cleanup failures after reclaiming it. `started`, `closed`, `process`, `source_generation`, `publication_id`, `latest` are observable. Each restart creates a fresh cancellation event/slot/shared allocation and increments generation; publication_id increases within that generation.
- `LatestFrameSlot.publish(packet)`, `read()`, `wait(*, after: tuple[generation, publication_id] | None = None, timeout=None)`, `close()`. One retained packet; strictly increasing identities; close wakes waiters and rejects later publications. No per-consumer image copy.
- `CaptureSample(image, geometry, received_at_ns)` is the child-local native result. `DXcamSource(settings, *, camera_factory=None, geometry_adapter=None)` implements native `start/read/close`; it is intentionally used only by the supervisor child. `read()` returns `CaptureSample | None`. Fake factories/adapters appear only in tests.
- `FramePacket` preserves all M1 positional fields and adds optional trailing `geometry: GeometrySnapshot | None = None`. If supplied, snapshot identity and frame dimensions must match the packet. Existing synthetic replay manifests retain their geometry_id-only contract and cannot enable input. Live packets always carry the immutable full snapshot.
- `GeometrySnapshot(client_rect, frame_size, content_rect, dpi=96, profile_id='legacy-1280x720', ui_scale=1.0, window_handle=0, profile_size=(1280,720))` normalizes coordinate sequences to immutable tuples. `geometry_id` hashes the complete snapshot. `recognition_supported` only accepts the preserved legacy profile, actual/reference/frame 1280x720, full content, UI scale 1, DPI 96. Mathematical scaling alone never establishes a recognized profile.
- Geometry methods: `frame_to_desktop(point)`, `desktop_to_frame(point)`, `roi_to_desktop(point, roi)`, `frame_box_to_desktop(box)`, `output_region(output_rect)`, `diagnostic()`. Out-of-bounds and nonfinite point inputs reject. Box right/bottom are exclusive boundaries. Diagnostic reports client/frame/content/profile dimensions, effective scale, supported status and proposed center. Application logs it on each new geometry identity from its actual packet.
- `WindowsGeometry(settings: GeometrySettings, *, api=None).snapshot(frame_size)` sets and restores per-thread per-monitor-V2 DPI context, locates the configured window and uses client bounds plus client-to-screen conversion. Missing, hidden, minimized, empty or unmappable windows fail closed. No border guesses or desktop fallback.

## Pinned native API and lifecycle evidence

Inspected installed DXcam 0.0.5 text without importing it: `.venv/Lib/site-packages/dxcam/__init__.py` exposes `create(device_idx=0, output_idx=None, region=None, output_color='RGB', max_buffer_len=64)`; `dxcam.py` exposes `grab(region=None)`, `start(region=None,target_fps=60,video_mode=False,delay=0)`, `get_latest_frame()`, `stop()`, `release()`.

`get_latest_frame` waits on a private event indefinitely. `_on_output_change` retries COM construction indefinitely without cancellation. DXcam module import enumerates adapters. Therefore only the child imports DXcam, creates its camera, invokes `grab(region=...)`, and calls `release()` in finally. The adapter never uses pinned recording `start`, `get_latest_frame`, private stop events, newer APIs, or abandoned daemon threads. The pin is unchanged.

The selected camera's pinned `_output.desc.DesktopCoordinates` supplies the monitor desktop origin. Client bounds are mapped to that output's relative crop, checked before capture, and checked again afterward with a new client snapshot. Moves during the grab discard the result. Unsupported/unestablished output mapping fails closed; no assumption relates a DXcam output index to Win32 monitor enumeration.

Native `grab` runs at managed configured cadence (default 60 FPS, configurable 120); this is a polling target, not measured throughput. Default no-frame returns publish nothing. Explicit artificial-repeat mode caches pixels only under unchanged geometry and carries the original successful receive timestamp unchanged. A genuinely acquired static image gets its real new receive time. A move away and back invalidates the cache, and restart discards it. No source render timestamp or distinct-presentation guarantee is invented.

Transport uses one fixed shared pixel array and an 8192-byte metadata buffer, protected by timed locking. Bounded independent error/cleanup buffers and aligned control words avoid reliance on a mutex a terminated child may own (supported Windows x64). Parent FramePacket makes the ownership copy while locked; metadata and pixels belong to that same publication. There is no full-frame FIFO, multiprocessing Queue feeder, or unbounded buffering. An old in-flight read keeps its original shared lock/generation/cancel event, so close/restart cannot redirect it to new geometry or publication state.

Stop first wakes parent waits and signals the child. The configured stop budget is split between normal join, terminate/join and kill/join; unreclaimed processes raise an explicit error. Time budgets bound waits/escalation, not OS scheduling or memory-copy execution time. Cleanup failures remain distinct from already-reported startup/read errors. Close drops the shared allocation after reclamation; retained FramePackets remain independently valid.

M5 boundary: `Application.stop` calls the non-waiting request_stop when available; `Application.close` is the capture wait boundary. Physical input is absent in M2. M5 must cancel/release input before this boundary, independently of capture errors. Do not put input ownership in the capture process.
