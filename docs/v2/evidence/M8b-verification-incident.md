# M8b preflight-test isolation incident

During initial M8b RED tests, `test_static_readiness_reports_missing_pinned_dependency_without_import` called the legacy `scripts.check_environment.run_checks` without the hardware import/driver trap used by the neighboring test. This was a verification safety error, not an authorized device validation. Original output: `logs/v2/m8b-build-red.txt` (7 failed, 9 passed in 4.37s). The worker will preserve this log with final M8b evidence.

Read-only inspection of the pre-change code at e2d7637 establishes that run_checks attempted its runtime imports, including DXcam, pyvjoy and the native route extension, then called check_vjoy_driver. Import exceptions are captured as result entries. The pytest assertion truncated that list, so the retained output cannot establish which native imports succeeded or the depth reached by the driver check. DXcam import can initialize DXFactory adapter enumeration; pyvjoy import can load its SDK DLL. The old vJoy check can query enabled/version/status/axis/button information and briefly acquire/relinquish an available device. Those effects cannot honestly be excluded from this test.

This call path does not invoke explicit frame grabbing, key/mouse/axis/button writes, installation, game launch or matchmaking. No such action was intentionally dispatched. This incident therefore does not establish successful hardware validation, and broad statements that all verification was device-free require this explicit exception.

The worker stopped these unsafe tests, inspected source/output without repeating the calls, and is adding shared import/driver traps to every legacy RED readiness invocation. Static readiness will inspect metadata/resources without importing hardware. The legacy preflight ownership acquisition will be removed with fake-API regressions, so explicit operator diagnostics do not acquire the device. Final test and review evidence must verify these corrections. The user was informed during execution of the certain attempts and the unproven native depth.

Corrective implementation and execution completed in M8b (independent review pending): static readiness uses package metadata/config/resources; guarded checker tests block legacy native imports/driver checks. Non-acquiring preflight fake-API tests reproduced two failures, then the covering preflight/checker/launcher group passed43 tests. Final unfiltered suite passed463. Original failing output is tracked at m8b/m8b-build-red.txt; corrective evidence at m8b/m8b-preflight-red.txt and m8b/m8b-preflight-green.txt; full implementation report in M8b.md. These results address prevention, not reconstruction of the earlier native depth.
